# Ground Truth Architecture: Dual-Stream Motion–YOLO Discrepancy Pipeline

## 1. Executive Summary & Problem Definition

### The Core Problem
In automated surveillance, standard object detectors (like YOLO) operate under a **closed-world assumption**. They are trained on specific classes (e.g., Person, Car, Bicycle) and treat everything else as invisible background. However, high-security environments often need to detect **Unknown Moving Objects** (e.g., a rolling piece of unrecognized equipment, a wild animal, falling debris) without triggering alarms for stationary background objects or standard moving traffic.

### The Pipeline's Purpose
This pipeline acts as an "Anomaly Motion Tracker." It identifies objects that are physically moving in the real world but are **not** recognized by your trained YOLO model. 

It accomplishes this via a **Mask-Level Discrepancy approach**: it captures *all* motion using classical pixel subtraction, captures *known* objects using YOLO, and dynamically subtracts the known objects from the motion mask. Whatever motion survives this erasure is guaranteed to be an unknown moving object.

---

## 2. Pipeline Architecture & Data Flow

The system is organized into four sequential modules. 

1. **Stream A (Motion):** Extracts all moving pixels regardless of class.
2. **Stream B (Semantics):** Extracts all known objects regardless of motion state.
3. **Module 3 (Erasure & Extraction):** Resolves the discrepancy by erasing Stream B from Stream A.
4. **Module 4 (Temporal Gating):** Filters out environmental noise and tracks the surviving unknown objects.

**End-to-End Input/Output:**
* **Global Input:** Unprocessed Video Frame `(H × W × 3 RGB)`, Timestamp.
* **Global Output:** Confirmed Unknown Bounding Boxes `[N, 4]`, Unique Track IDs, and optional cropped image patches of the unknown objects for future model retraining.

---

## 3. Detailed Module Specifications

### Module 1: Class-Agnostic Motion Extraction (Stream A)
* **What it does:** Identifies every pixel in the current frame that has changed compared to the historical background. 
* **Component Chosen:** **OpenCV MOG2** (Mixture of Gaussians).
* **Why it was chosen:** MOG2 explicitly models each pixel as a mixture of Gaussian distributions, allowing it to adapt to gradual lighting changes. Crucially, MOG2 includes built-in shadow detection, which flags moving shadows as a distinct value (127) rather than foreground (255), preventing the system from drawing bounding boxes around shadows.
* **Module Input:** Raw RGB Frame `(H, W, 3)`.
* **Module Process:**
  1. Feed the frame into the MOG2 background subtractor.
  2. Threshold the output to drop shadows (pixel value 127) and keep only pure foreground (pixel value 255).
  3. Apply a Morphological Opening (Erosion followed by Dilation) using a `5x5` kernel to eliminate salt-and-pepper sensor noise and tiny rustling leaves.
* **Module Output:** Binary Motion Mask `(H, W, 1)`.

### Module 2: Known-Object Detection (Stream B)
* **What it does:** Identifies the bounding boxes of all objects the system already understands (e.g., people, vehicles) in the current frame.
* **Component Chosen:** **Ultralytics YOLO** (v8 or v11).
* **Why it was chosen:** YOLO is the industry standard for real-time edge inference. It processes the whole image in a single forward pass, providing the high-speed "known world" baseline required to keep the dual-stream pipeline running at 30+ FPS. 
* **Module Input:** Raw RGB Frame `(H, W, 3)`.
* **Module Process:**
  1. Forward pass through the YOLO network.
  2. Apply Non-Maximum Suppression (NMS) to remove overlapping predictions.
  3. Filter out low-confidence detections (e.g., `< 0.40`).
* **Module Output:** Array of Known Bounding Boxes `[K, 4]`, formatted as `(x1, y1, x2, y2)`.

### Module 3: Mask-Level Erasure & Extraction (The Discrepancy Engine)
* **What it does:** Removes the motion generated by "Known Objects" so only "Unknown Motion" remains. It then draws bounding boxes around the surviving motion blobs.
* **Component Chosen:** **Custom Matrix Masking + OpenCV `findContours`**.
* **Why it was chosen:** You cannot simply compare bounding boxes between Stream A and Stream B using Intersection-over-Union (IoU). If a known person is walking while pushing an unknown cart, their bounding boxes will overlap. **Mask-level erasure** paints the YOLO bounding box *black* on the binary motion mask. This cleanly amputates the person from the motion mask, leaving the pixels of the cart intact to be grouped into a new bounding box.
* **Module Input:** Binary Motion Mask from Module 1, Array of Known Bounding Boxes from Module 2.
* **Module Process:**
  1. **Dilation Margin:** Expand each YOLO bounding box by 10% (Padding). This is critical because YOLO boxes are often tight; if a person's swinging arm breaches the YOLO box, those arm pixels will trigger a false "Unknown" object.
  2. **Erasure:** Set all pixels inside the padded YOLO boxes on the Binary Motion Mask to `0` (black).
  3. **Contour Extraction:** Run `cv2.findContours()` on the residual mask.
  4. **Area Filtering:** Discard any contours smaller than a minimum pixel area (e.g., `< 500` pixels) to ignore insects or rain.
  5. **Bounding Box Generation:** Calculate the `cv2.boundingRect()` for the surviving contours.
* **Module Output:** Array of Candidate Unknown Bounding Boxes `[U, 5]`, formatted as `(x1, y1, x2, y2, confidence)`. (Confidence is hardcoded to 1.0 for the tracker).

### Module 4: Temporal Trajectory Gating (Noise Filtering)
* **What it does:** Tracks the candidate unknown boxes across multiple frames to verify they represent physical objects moving with intent, rather than transient environmental noise (like a swaying tree branch or a flashing light).
* **Component Chosen:** **ByteTrack** (Standalone Python Implementation).
* **Why it was chosen:** ByteTrack associates bounding boxes using Kalman Filter motion predictions and IoU. It is chosen over DeepSORT because ByteTrack does not require extracting deep visual appearance features (Re-ID). Since we are tracking *unknown* objects, we don't know what they look like, making Re-ID unreliable. ByteTrack is purely geometric and incredibly fast.
* **Module Input:** Array of Candidate Unknown Bounding Boxes `[U, 5]`.
* **Module Process:**
  1. Feed candidate boxes into ByteTrack to update existing tracklets or instantiate new ones.
  2. **Directional Persistence Check:** Calculate the centroid of each track. If an object is oscillating in place (centroid moves back and forth but net displacement is near zero, like a swaying tree), flag it as noise.
  3. **Frame Survival Gating:** Do not output a bounding box until the Track ID has survived for `W` consecutive frames (e.g., `W = 5`). This kills 1-frame glitches caused by sudden camera auto-exposure adjustments.
* **Module Output:** Confirmed, persistent Unknown Moving Object coordinates and their unique Track IDs.

## 4. Summary of Data Transformations

| Processing Stage | Data State In | Data State Out | Semantic Meaning |
| :--- | :--- | :--- | :--- |
| **Stream A (Motion)** | `(1920, 1080, 3)` RGB array | `(1920, 1080, 1)` Binary mask | "Here is everything moving in the scene, plus some noise." |
| **Stream B (YOLO)** | `(1920, 1080, 3)` RGB array | `[K, 4]` coordinate matrix | "Here are all the people/cars, regardless of whether they are parked or moving." |
| **Mask Erasure** | Binary mask + `[K, 4]` boxes | Mask with holes punched in it | "Here is the motion mask with all known people/cars digitally erased." |
| **Contour Extraction**| Mask with holes | `[U, 5]` coordinate matrix | "Here are the rough bounds of the surviving unknown moving blobs." |
| **Temporal Gating** | `[U, 5]` coordinate matrix | Validated `[V, 4]` boxes + IDs | "Here are the final unknown objects that follow real physics trajectories." |

## 5. Active Learning Loop (Next Steps)
Because this pipeline reliably isolates unknown moving anomalies, it inherently acts as a data-mining engine for your future AI models. You should implement a final hook that triggers on Module 4: whenever an Unknown Track survives for more than 30 frames, use its bounding box to crop the original RGB frame and save that image to a local folder. This automatically builds a highly curated dataset of edge-case objects specific to your surveillance environment, which you can later label and train into YOLO Stream B.
